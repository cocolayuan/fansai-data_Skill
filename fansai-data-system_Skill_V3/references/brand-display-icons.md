# 品牌展示图标：V15 静态资源与接入规范

本参考管理 FansAI 品牌升级中的**展示图标阶段**，用于大面积业务入口、分类选择、功能引导和专题重点区。它与平台的小尺寸功能图标分工；不得仅把旧平台 palette 换色就视为完成本次图标升级。

资源基线为用户提供的「FansAI-融合像素图标-静态版」，源 manifest 标识 **V15 / static**。本包没有独立 Logo 本体，不能宣称已核验 Logo 几何继承、重绘 Logo，或已完成整个 branding / 全平台升级。Logo、字标及其他品牌资产继续使用各自批准的原件。

## 1. 场景边界与视觉构造

- **适用**：审批事项卡、业务分类选择、功能入口、独立引导图和少量重点展示区。
- **不适用**：导航、按钮、工具栏、输入框、状态标签、表格行中的 16–32px 功能 icon；64px 以下的装饰点缀也不加载本库。继续使用平台既有简洁线性功能 SVG，方形导出并不是小图标版本。
- **静态优先**：图像不添加波纹播放、闪烁、位移或像素噪声动画。容器可有轻量 hover 与清晰 focus 反馈，图像保持稳定。

| 阅读层次 | 已有构造 | 扩展时必须保留 |
|---|---|---|
| 业务轮廓 | 文件夹、文档、箱体、双人等熟悉主体 | 可辨认的业务含义和关键负形 |
| 微符号场 | 圆点、方点、短笔画等形成连续纹理 | 主体和背景使用同一图形语言 |
| 空间秩序 | 波纹状、同心或绕行流线，以明度、密度和方向形成重心 | 主体清晰，外围较轻，纹理不压过轮廓 |
| 分类信息 | 横图内的 1–9 序号，以及图外标题和说明 | 序号仅是浏览索引，文字承载准确语义 |

这些是视觉解构，**不是要求拆成四个独立图层**。源 manifest 为 `single micro-symbol field`、`foregroundLayer:false`、网格步进 2.4（源画布单位）。不能在彩色纹理上贴普通实心图标，或给任意轮廓套噪点滤镜来替代微符号融合。

## 4. 已核验的源文件事实

包内共 **45 份资源（9 项 × 5 格式）**。catalog 的 `files.*.path` 均相对 skill 根目录，包含文件尺寸、字节数和 SHA-256；资源仍位于 `assets/banner-svg` 等原路径。

| 资源目录 | 原始尺寸 | 序号 | 使用说明 |
|---|---|---|---|
| assets/banner-svg | 360×144，2.5:1，圆角 12 | 内嵌 | 完整横向画面，SVG 可放大 |
| assets/banner-png-2x | 720×288 | 内嵌 | 360 CSS px 宽的 2× 图像 |
| assets/banner-png-4x | 1440×576 | 内嵌 | 360px 的 4× 或 720px 的 2× 图像 |
| assets/square-svg | 128×128，1:1，圆角 20 | 无 | 独立方形构图，不是横图裁中间 |
| assets/square-png-4x | 512×512 | 无 | 128px 的 4× 或 256px 的 2× 图像 |

- 横向九张 SVG 共 4,142,917 字节，每张约 431–492KB；方形共 1,288,988 字节。微符号路径复杂，不能按普通小 UI icon 估算开销。
- 横图数字为 21px / 600，底板 32×32、圆角 8，源坐标 x318 / y8，即上 8px、右 10px。SVG 与 PNG 都已内嵌，不再叠一套 HTML 序号。
- 所有 SVG 均使用 `id="frame"`；原图无外部引用、脚本和动画。它们是有背景的完整画面，不是透明符号。
- 源尺寸、配色、构图、角标和 hashes 是文件事实；以下显示下限和布局规则是新增的实现默认，不能混称为源文件已有的测试结论。

## 5. 新增显示与布局默认

先按**实际 CSS 显示尺寸**判断可辨识度，高分屏导出像素数不替代显示尺寸。

| 格式 | 新增最低显示尺寸 | 建议范围 |
|---|---|---|
| 横图 | 240×96 CSS px | 宽 280–400px，保持 2.5:1 |
| 方图 | 128×128 CSS px | 160–240px，保持 1:1 |

最低值仍需在实际页面核对，难以辨认时继续放大或改用文字与功能图标。

- 卡片主体纯白 `#FFFFFF`，无日常线性描边；留白与轻微阴影分层。当前审批中心的极浅灰蓝绿仅用于弹窗内容底层，不外推为全平台底色。
- 卡片保留图像、真实标题和一句功能说明，用图外可访问 DOM 文本呈现；不加无关口号、AI说明或操作废话。
- 审批选择卡默认内边距 12px、间距 28px；标题 16–18px / 600，说明 11–12px，说明色可沿用平台 `#64748b`。
- 三列内容区至少 848px（3×264＋2×28）；两列至少 556px；单列至少 264px。390px 手机宜单列。容器不足时减少列数，不裁图、缩字或压缩到显示下限以下来维持九宫格。
- 外层可用宽度少于 264px 时改文字＋功能图标，或重新安排布局；不要把大图硬塞入窄容器。若需要严格桌面三列，不用可能扩成四列以上的无限 `auto-fit`。
- 展示图集中在入口或重点区域；不在每个字段、表头和表格行重复彩色画面。键盘焦点可使用清晰轮廓线。

## 6. 接入与原件保真

1. 从 catalog 按 ID 匹配资源和说明，例如 `outsourcing_payment` 对应 `assets/banner-svg/08-outsourcing-payment.svg`。保持业务字段、权限和审批流程语义。
2. 优先 `<img>` 引用独立 SVG 或适当分辨率 PNG；按需加载与缓存。离线单文件才嵌入所用资源，不为每个实例重复内联全库。
3. 保持原宽高比，默认 `object-fit:contain`，不用 `cover` 裁主体或角标，不拉伸、不用 `currentColor`、CSS filter、混合模式或抠底重染。
4. 多枚 SVG 必须内联时，为派生副本的所有 ID 和相应 `url(#...)` 引用加唯一前缀，避免 `frame` 冲突。
5. 横图序号为索引，不是业务数量；不重复叠加。需要无序号、改序号、等距角标或暗色重绘时，另建标识清楚的派生文件，核对 SVG/PNG 一致并保留原件。
6. 图与相邻标题语义重复时 `alt=""`；独立传达含义时用简短 alt。交互放在外层按钮或链接，标题供名称、说明供描述，支持整卡点击和键盘焦点。
7. 深色页面可用独立白色展示容器承载原图；不要反色整个图。无匹配业务资产时使用既有功能图标或提出新增图需求，不复用含义不符的审批图。

## 7. 延展与验收

新增图先选独特业务轮廓，再以同一微符号场构成主体和流线；与原九项并排核对大小、视觉重量、重心、留白与纹理强度。没有原始生成器时，不承诺从现有路径自动生成任意新业务图；新增资产先作为候选审阅。

交付时核对：九项名称 / ID / 功能说明 / 色板正确；08 蓝灰；资源完整加载；目标 CSS 尺寸可辨识；无裁切、拉伸或重复序号；整卡点击和焦点有效；内联 ID 无冲突；原件 hashes 保持一致。V3 升级应落实到资产选用、尺寸边界、容器、语义文字和接入规则，而不是只改旧平台 palette。
