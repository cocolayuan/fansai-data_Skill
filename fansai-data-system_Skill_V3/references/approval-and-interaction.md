# 审批中心与交互 · V3

将本轮已确认设计收纳为可复用规则。业务字段、状态条件、权限、审批流及真实数据由原需求决定；视觉规范不能改写这些事实。尺寸是默认实现值，可按实际可读性调整，不是所有页面的硬性固定宽高。

## 1. 表面与颜色的作用域

| 层次 | V3 默认 | 边界 |
|---|---|---|
| 平台页面 | 原 V2.1 body 薄荷弥散背景 | 不因为弹窗改色而换全局主题 |
| 遮罩 | 轻半透明中性色 + 背景模糊 | 保持前景文字对比，内容不能被透色冲淡 |
| 审批弹窗滚动底层 | `#F1F6F6` 极浅灰蓝绿 | 只作用于弹窗，不作为整页主色 |
| 前景模块 | `#FFFFFF` | 入口卡、资料卡、评论编辑器和附件卡白底，不叠深灰蓝面 |
| 表格行面 | 白色 / `#F7F9FB`；hover `#EEF5F8` | 用轻水平线组织行，不画厚纵横格，不给每个字段套框 |
| 文本与操作 | 墨 `#1B2430`，辅助 `#64748B`，弱元信息 `#94A3B8`，链接 `#008AA8` | 关键值不得用弱元信息色；品牌展示图配色不承担状态语义 |

无描边指卡片和选项的**默认外观**。输入边界、校验错误、分隔线、键盘焦点仍须可辨。语义色继续取主规范 `STATUS_STYLE`。

## 2. 审批列表与侧栏

- 表格顶部合并标题、搜索与筛选；表头轻、业务标题清楚，客户与项目元信息分层。金额右对齐，用等宽数字；时间显示准确完整的业务值。
- 以细水平分隔 + 浅行面建立秩序，不把所有行做悬浮卡、不用粗纵向框。行 hover 不改变行高；固定操作列与所在行底色一致，避免透明穿字。
- 行上的“处理 / 查看”是进入详情的入口，可用白底轻描边或浅面按钮；最终审批的墨色主操作留在详情底部。不要套用旧操作列配方给每行制造多个主按钮。
- 筛选保留全部真实选项和对应关系。状态列表基于所在业务范围/权限，不为美观伪造“已通过”等不可用状态；必要时保留合法的无结果选项并呈现空态。状态、类型、页大小、同事选择共用面性下拉视觉。
- 左侧目录默认约44–46px高，13–14px字、10–12px圆角、4–6px行距，保留名称和小计数。去重复解释副标题；长名称可换行。桌面紧凑不应造成触控困难。
- 当前目录墨色 `#1B2430` 实底；“发起审批”约44px高、500字重，灰蓝墨色 `#45565F` / hover `#344750`，轻微弱化阴影。此局部入口例外不改全站提交主按钮。

## 3. 发起审批与九类入口

- 点击左下角入口打开**居中弹窗**，不是侧抽屉。分类和搜索保留；选中一类再进入该类原有字段表单，取消返回行为明确。
- 使用 [品牌展示图标规范](brand-display-icons.md) 的 V15 静态资源，横图完整2.5:1，不叠加重复编号。
- 白色卡片默认无描边，桌面间距28px（可24–32px），内边距12px，标题16–18px / 600，保留 catalog 中一句功能说明，建议12px。整体控制紧凑，不再堆说明条、口号或重复底部提示。
- 保留足够图面辨识空间：图宽至少240 CSS px，卡宽至少264px。以实际容器内宽决定列数：≥848px三列，556–847px两列，264–555px一列；更窄改为功能图标+文字。
- 例如桌面弹窗最大宽984px、两侧30px，内宽924px，三列卡约289px、图面265px。视口缩小时先减列数；不能为“缩小20%”永久强制裁图、缩字或保持九宫格。
- 弹窗限高 `calc(100dvh - 48px)`，内容超高内部滚动，关闭按钮始终可见。窄屏两侧留16–24px，不出现横向页面溢出。

## 4. 详情与资料表

固定标题/状态/关联业务与标签页，主体内部滚动，底部操作固定；保留“审批详情 / 审批记录 / 全文评论”。滚动区须 `min-height:0`，不让页头、编辑器、操作栏各自挤占整屏。

- 删除详情标题旁难辨识、无信息的小像素贴图。真实项目/申请业务标题24–26px、600–700；窄屏约21px。通用“审批申请详情”标题20–22px，避免抢业务标题。
- 资料前景白底；按申请信息、业务信息、附件分组。核心金额/结果优先，申请人/时间作为元信息，说明单独一行；不改变完整字段与关联信息。
- 标签用辅助色、值用墨色；主要字段通过字号/留白区分，不给整表铺蓝绿。段标题、行面、少量水平细线共同组织资料。
- 禁止以标题重复为理由删真正字段；重复装饰文案可去除。完整字段核对依据原业务需求，不依据截图可见区域。

## 5. 审批操作分层

| 状态 | 局部区域 | 底部工作流操作 |
|---|---|---|
| 待处理 | 不展开子表单 | 按权限显示“转交”“驳回”“通过审批”，仅通过为主操作 |
| 转交中 | 同事选择 + 紧邻的“确认转交”；同区提供取消 | 三项入口保留位置并暂时禁用，当前主操作仅局部确认 |
| 驳回中 | 按业务要求填写原因，确认与原因输入同区 | 同上，提交/取消后恢复可用状态 |
| 提交中 | 当前确认显示处理中并锁定重复提交 | 禁止并发通过、驳回或转交，保留处理结果反馈 |
| 完成/无权限 | 呈现实际结果与可查看信息 | 只显示该状态真正可用操作，终态不放假主按钮 |

同事选择器、确认和取消同一组，宽屏并排；窄屏紧跟换行，不能隔着大块空白放到右下角。未选同事不可确认。取消还原之前草稿；失败保留输入并允许重试。通过/撤回等是否二次确认取决于已有业务要求，不因本规范增加多余层层弹窗。

“我提交的”是否展示催办/撤回、“抄送我的”是否只读，依已有角色与状态规则；不要将待审批操作复制给所有标签。

## 6. 评论与附件

借鉴协作工具的阅读顺序：**头像 → 姓名/时间 → 正文 → 附件 → 回复等操作**。人员头像继续沿用平台圆形及确定性分配规则。内容区适当限制行宽；不做聊天气泡式大色块，回复以缩进或轻层次表达。

- 评论列表滚动，输入区固定在评论区底部，与最底层审批操作栏区分。白色编辑器、白附件卡、克制灰蓝元信息；当前可执行发送用平台墨色。
- “回复”紧邻对应评论；回复对象可取消，长回复组可收起。仅本人评论提供删除入口，按实际权限与确认规则执行。
- 空评论且无附件时发送禁用；非空正文或合法附件才可提交。支持 Cmd/Ctrl+Enter，输入法组合态不触发。提交时冻结当前草稿与附件，防止重复、串帖或删除错位；失败保留草稿。
- 文档附件用**文档页缩略示意**或文件类型图标 + 文件名/真实元信息，不再用山峰风景占位图冒充资料。示意图明确标示，不伪装真实文件内容；真实图片才显示图片缩略图。
- 附件预览关闭后回到原评论位置和触发点。可移除待上传附件，删除/回复不能误触底层审批；异步完成时以稳定记录ID对应，不能只依列表索引。

## 7. 简洁文案与验收

保留信息：功能说明、字段名称、真实业务说明、必填/错误提示、文件元信息、可访问名称、示例标记。删除无信息的“按业务场景选择”“随后填写资料”等重复导语和 AI 口吻补白。不将这条解释为删除九张入口卡的功能说明。

无后端的演示页必须清楚标示“示例”；产生状态变更时反馈仅本地生效。正式接入必须实现权限、接口、上传与审批状态机，单文件HTML原型本身不代表后端已完成。

按受影响部分验收：

- [ ] 原有审批类型、字段、选项、数据记录及业务ID未因视觉升级变化。
- [ ] 1440×900与窄屏下，九图完整、白卡有功能说明、所有下拉不裁切；焦点可见。
- [ ] 目录紧凑；列表金额/状态/操作明确，主体无横向溢出，必要表格内部滚动可用。
- [ ] 详情没有缩小展示图贴片，浅底只在弹窗层；资料和评论前景白色。
- [ ] 转交/驳回确认紧邻输入，当前步骤仅一个强主操作，无并发提交。
- [ ] 回复、取消、附件预览、删除和输入法发送边界可用；取消关闭恢复合理焦点。
- [ ] 检查实际保存文件，区分脚本检查与实际浏览器验收；未测项如实交代。
