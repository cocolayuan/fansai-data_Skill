# FansAI 数据中台 · 工作台与复合数据页规范

适用于 FansAI Database 全系统的一级/二级/三级工作台、复合列表、层级数据、时间节奏、操作菜单和业务弹窗。客户资料系列页面是这套规则的首个完整验证范例，不是适用边界。

**全系统默认约束**：除第 9 节明确标注为「客户资料业务映射」的内容外，本文件所有规则都应在数据看板、项目、内容、创作者、供应商、流程、账号、客户等页面按场景复用。没有对应数据形态时不强行添加模块。

## 1. 全系统适用范围与页面选择

- 先判断数据关系，再选页面形态；不要把某个成功页面的所有模块无差别复制到全系统。
- 概览/看板：强调关键数字、结构、趋势与异常，不强加明细操作列。
- 平级记录：使用表格或卡片列表；字段多时内部横向滚动，视觉资产多时改用卡片。
- 主记录—子记录：使用可展开层级行；父级显示聚合，子级显示自身状态。
- 有连续时间语义：提供节奏/表格双视图，时间窗口局部滑动；无时间语义时不造时间轴。
- 新建、编辑、审批、安排等短流程：使用统一居中弹窗；长流程或跨模块配置才使用独立页面。
- 同一模块的顶层 tab 切换不改变 header、工具栏和视觉语言。
- 源截图和源 HTML 不一致时，**截图是 final 版本**；不得为了填满页面补造记录、字段、负责人或分类。

## 2. 页面骨架与 1440 适配

### 2.1 首选结构

```text
面包屑 / 用户区
同模块视图 / 状态 tab（有则显示）
运营概览（有真实指标时显示为一个大面板）
搜索 + 筛选 + 视图切换 + 新建/新增主记录
主工作区（默认视图 / 审计表格视图）
图例 / 口径 / 分页
```

- 优先适配 **1440 × 900**。搜索框收窄，让搜索、主要筛选、视图切换和主按钮尽量在同一行。
- 只有容器确实不足时才换行；不得为了固定一行而把按钮压到不可读或低于 40px 点击高度。
- 同组运营数字放在一个玻璃面板中，用细分隔线组织，不拆成一排漂浮卡；没有真实指标时整段不渲染。
- 页面显示数据截止时间，例如 `数据截至 2026-08-18 23:59`，并注明 `每日更新至前一日`。时间以实际数据日为准，不写浏览器当前时间冒充数据时间。

### 2.2 已注册运营语义色

| 指标 | 数字色 | 用途 |
|---|---|---|
| 停滞待唤醒 | `#FF4F23` | 需要立即处理 |
| 七天内有安排 | `#FFA723` | 已进入近期计划 |
| 可发起立项 | `#12B89D` | 满足转项目条件 |
| 没有下一步 | `#74A3AB` | 缺少计划但非错误 |

色彩只落在数字、状态点或短强调上；大面积背景继续用白色/玻璃色。

## 3. 主记录—子记录层级

- 父行显示主记录聚合信息；子行只显示自身字段。适用于客户—项目、项目—任务、部门—成员、流程—节点等真实层级。
- 组织类主记录可使用中性两字头像，如「青禾」「润图」；子记录不重复添加无信息图标。
- 首标左侧保留统一的 40px 展开槽：有子项显示箭头，无子项保持空槽，主标题永远同一基线。
- 组织头像走中性薄荷灰；人员头像可用确定性色。不要把组织头像和人员头像混成同一套视觉。
- 子行不重复父级负责人；只有子记录源数据明确提供独立负责人时才显示，否则为 `—`。
- 分支线限定在首列内，不越过阶段/金额列。竖线与横线均为细、稀疏、圆头虚线。

```css
.branch-v,.branch-h{
  stroke:#c6dcda;stroke-width:2;stroke-linecap:round;
  stroke-dasharray:2 10;
}
```

## 4. 节奏视图与局部时间轴

节奏视图适用于客户跟进、项目推进、审批、交付与排期等连续时间数据。它回答三个问题：现在在哪、最近发生了什么、下一步什么时候。

### 4.1 只滑动时间轴

- 左侧实体信息、阶段、金额和右侧操作固定；只有「两周前—下一周」时间轴窗口可横向滑动。
- 表头时间刻度与所有行共用同一个 `scrollLeft`，始终同步。
- 大表格本身不横向滚动；避免用户滑完时间后丢失主记录名称和操作入口。
- 时间轴表头的基线两端放轻量左右箭头，既是可滑动提示，也是可点击按钮；到边界后禁用对应方向。
- 鼠标滚轮在时间轴区域转换为横向滚动；触控板可直接滑动。

```css
.timeline-viewport{overflow-x:auto;overscroll-behavior-inline:contain;scrollbar-width:none}
.timeline-track{min-width:900px;display:grid;grid-template-columns:repeat(5,minmax(180px,1fr))}
.actions-col{position:sticky;right:0;background:rgba(255,255,255,.96);z-index:5}
```

```js
const viewports=[headViewport,...rowViewports];
let syncing=false;
viewports.forEach(v=>v.addEventListener('scroll',()=>{
  if(syncing)return; syncing=true;
  viewports.forEach(other=>{ if(other!==v) other.scrollLeft=v.scrollLeft; });
  requestAnimationFrame(()=>syncing=false);
}));
```

### 4.2 时间刻度与符号

- 可见窗口刻度按源页面使用：`两周前 / 上一周 / 今天 / 本周内 / 下一周`。
- `今天`有细短竖线和深色文字，不用整列重色背景。
- 图例必须跟随页面底部，并与实际符号逐项一致；截图中的图例是字段与文案的最终依据。
- 建联/更早动态：空心圆或菱形；跟进动态：薄荷实点；最近动态：带柔光大点；下一步：橙色虚环；我方交付：橙色方框；更远安排：橙色空心圆；四周以外：小三角；已排接触区间：薄荷虚线；停滞天数：橙红虚线。
- 时间轴说明文字统一使用与「停滞 28 天」同级的小字号；`已排期`、`已推进完成`、`审批流程进行中`不得忽大忽小。
- 包含 `·` 的下一步文案在窄列中让分隔点后的文字换行，避免第二段被挤成孤字。

## 5. 表格视图

- 表格视图用于完整字段核对，字段顺序以源页为准；客户页面可包含客户、状态、客户类型、项目、项目类型、BD、阶段、预测金额、周期归属、建联、最近动态、下一步、停滞、来源、跟进状态、操作，其他模块映射为对应真实字段。
- 字段过多时允许**表格内部**横向滚动；首个主记录列 sticky，且每行必须有不透明背景，不能滑动后露出下层文字。
- 表头、斑马纹、选中态和 sticky 列必须共享同一行背景变量。
- 缺失值统一 `—`；删除没有来源依据的 `Pipeline` 等解释文字。
- 右侧操作列保持可见，按钮和箭头距容器边缘至少 16px。

```css
.table-scroll{overflow-x:auto}
.primary-col{position:sticky;left:0;z-index:3;background:var(--row-bg,#fff)}
tr:nth-child(even){--row-bg:rgba(239,248,247,.72)}
thead .primary-col{z-index:4;background:#f8fbfb}
```

## 6. 阶段、状态与语义色

- 阶段表达 = 普通文字 + 四段进度条，不把 `已推进完成` 做成 tag。
- `已推进完成` 使用明亮绿色进度条；文字保持与 `需求沟通` 同一深墨色、字号和字重。
- `已排期`、`审批流程进行中`也沿用同一正文规格；颜色用语义点/进度条表达，不靠放大文字。
- 同一主记录下的子记录可处于不同阶段；聚合父行展示真实计数，不能给全部子项套同一完成态。
- 立项审批显示实际流程人员，例如 `Harrison → Jessie → Mia → ZZ`，突出当前节点；点击后打开审批进度弹窗。

## 7. 右侧操作与更多菜单

- 每行右侧采用 `主/次操作 + …`。只提供源页面存在的动作；若源页只有「查看项目」，不得额外造「去项目管理」。
- 按钮规格与 V2 列表页一致，最右留 16–20px 安全距离；`…` 使用独立方形按钮，不与主按钮挤在一起。
- 菜单固定定位并锚定触发按钮，靠近底部时向上翻，靠近右侧时向左对齐，不能被表格 overflow 裁切。
- 菜单按时间分组：
  - 已发生：记录一次动态
  - 当前：更新阶段
  - 接下来：安排下一步、新增子记录
  - 分隔项：编辑主记录
  - 危险项：退回/归档；客户资料场景映射为「退回线索池」
- 图标统一使用 IconPark 线性 SVG：图标 16×16，外层锚点 32×32，圆角 10px，线宽/颜色一致；禁止混用 emoji、文字字符和不同来源图标。

## 8. 弹窗与表单控件

### 8.1 弹窗家族

新建、编辑、审批进度、安排时间、记录动态、更新阶段、增加子记录、退回/归档等短流程都使用**居中弹窗**，严格复用 `content_asset_modal_reference.html` 的视觉语法：

- 半透明遮罩 + 背景模糊；白色/玻璃弹窗；圆角 26–30px。
- `header / scrollable body / sticky footer` 三段结构；关闭按钮在右上安全区。
- 表单章节放进描边卡片，标题、说明和必填状态清楚；不在 modal 顶部添加无意义英文 eyebrow。
- 主按钮墨色实底，次按钮白底描边，危险确认使用红橙语义；按钮顺序全站一致。
- 所有操作都要可关闭、可取消；无后端演示需注明仅在当前 HTML 生效。

### 8.2 下拉与日历

- 禁用原生 select 的浏览器默认样式。箭头拥有独立 40px 安全区，文字不得贴到箭头。
- 下拉浮层使用 `position:fixed` 逃离滚动裁切，并根据视口空间自动向上/向下展开。
- 日期输入使用自定义日历：年月标题、前后月、星期、当月/跨月日期、选中日、今日、清除；日期格式统一 `YYYY/MM/DD`。
- 日历同样自动翻转和限宽，不得溢出 modal；点击遮罩或 Esc 关闭。

```css
.select-trigger,.date-trigger{padding:0 52px 0 18px;min-height:48px;position:relative}
.select-arrow,.calendar-icon{position:absolute;right:14px;width:24px;height:24px;display:grid;place-items:center}
.popover{position:fixed;z-index:1200;max-width:calc(100vw - 24px)}
```

## 9. 客户资料业务映射范例

- 客户资料模块顶层包含**客户库**与**线索池**；这两个 tab 是客户业务映射，不要求其他模块照搬。
- 线索池保留独立字段：线索名称、来源、备注、进池日期、退回原因/说明、历史纪要、操作。
- 未认领前不显示虚构负责人、停滞天数或客户节奏；公共线索不占个人客户名额。
- 行操作以「认领并建联」为主；有真实历史时才显示「看历史」。
- 「退回线索池」不是删除：释放归属权，保留历史纪要，并要求填写原因。
- 一个客户可以有多个项目，且项目阶段、金额、下一步、审批状态可各不相同；客户聚合值必须来自其项目。
- 顶部说明只解释生命周期与归属，不写实现文档式长段落；复杂规则可放 tooltip/帮助入口。
